# 趣味小屋：技术方案

状态：用户已确认并授权实施，现已实现。

## 实现选择

原生 HTML、CSS、JavaScript ES Modules，静态部署，无框架和运行时第三方依赖。现有目录为空，无历史系统需要兼容。使用 Sites 的静态网站流程；方案确认后创建网站，最终提供可访问的私有预览，发布结果以工具返回状态为准。

选择依据：功能均为本地交互，内容量小，无需数据库、鉴权或服务端。若后续加入云同步、投稿或管理后台，应另立需求和方案。

## 结构

- dist/index.html：中文页面与语义化结构。
- dist/styles.css：响应式、焦点和减少动态效果样式。
- dist/js/app.js：视图切换、事件与渲染。
- dist/js/core.mjs：搜索、去重、随机选择和文字统计的纯函数；随机源可注入用于验证。
- dist/js/storage.mjs：版本化收藏、本地存储异常与会话回退。
- dist/js/content.mjs：稳定 ID 的预置内容。
- tests/：Node 内置测试运行器；运行环境与命令在实施时记录。

文档存于本目录；应用在独立项目子目录实现，避免混入交付文档。最终补充运行说明、来源记录和验收报告。

## 视觉与交互

温暖轻松的小屋主题：奶油底色、暖棕文字、橙色与绿色点缀。桌面采用清晰导航和卡片内容区，手机使用紧凑可换行导航。装饰不影响可读性与功能入口。无需外部图片即可完成首版；不增加图片生成或复杂动画依赖。

按钮使用原生 button；工具有 label；当前分类有可读状态；操作结果通过 aria-live 提示。外链标明来源。内容和用户输入使用 textContent 或安全 DOM 创建，不使用用户输入拼接 HTML。

## 状态与算法

收藏 key 使用 fun-house:favorites:v1，保存 schemaVersion 和内容 ID 列表。读取数据校验结构和版本；异常进入会话模式并展示提示。页面重新加载时重新读取。

使用浏览器伪随机数满足休闲工具需求；不用于有奖、公证或密码用途。选择器先去重再均匀取索引；“换一条”先排除当前 ID；随机整数计算覆盖闭区间。测试使用注入随机源覆盖端点，不用脆弱的抽样频率断言证明均匀。

复制使用 Clipboard API，捕获权限或上下文错误。工具输入不上传；收藏仅存内容 ID。首次加载仍需网络，不承诺离线可用。

## 验证策略

1. Node 内置测试覆盖 core、storage 的实质边界和故障路径。
2. 浏览器验证完整旅程、刷新持久化、复制、异常反馈、键盘及四档宽度。
3. 内容逐条查证，记录 URL、对应陈述和核对日期；测试只检查结构，不能代替事实核查。
4. 发布前逐项填写 AC-01–AC-10；测试失败先修复，工具不可用则如实记录限制。
